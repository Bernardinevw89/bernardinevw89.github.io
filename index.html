01 / Diagnose

Start where the shopper is.

I started in technical support. Before asking for access, I opened the merchant’s storefront and followed their steps. Tracing the behaviour helped me work out whether the theme needed a fix or an app developer needed a clear reproduction.

Help Scout · Storefront inspection

02 / Resolve

Make the fix safe to try.

When support began escalating tickets to me, I investigated on a duplicate theme. The merchant got a preview they could test and publish in their own time. I turned repeat fixes into Notion tutorials and filed GitHub issues so the underlying bug could be addressed for future installs.

Trello · Liquid · Notion · GitHub

03 / Build

Turn a design into a working theme.

I built sections and features from Figma, contributed to complete theme builds, and took sprint tickets through testing and lead review. I also onboarded new developers and kept handling escalations alongside planned work.

Liquid · HTML · CSS · JavaScript · Figma · Git

04 / Extend

Follow the product into apps.

I learned React by building an internal practice app from scratch. Then I spent several months contributing sprint work to Kitenzo, a bundle-building app I already knew from supporting its merchants.

React foundations · App development · Sprint delivery

05 / Review

Own the quality of the change.

Back on themes, I helped modernise existing products and tested both my own work and my teammate’s. When our workflow shifted to Claude Code, I reviewed generated implementations for code quality and checked the storefront against the requirements.

Peer QA · Code review · AI-assisted development
