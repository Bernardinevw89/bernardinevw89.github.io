01 / Diagnose

Diagnosing Shopify storefront issues.

I reproduce storefront issues from the merchant’s steps and trace where the behaviour breaks down. At Eight, I did this before requesting store access so I could tell whether the theme needed a fix or an app developer needed a clear reproduction.

Help Scout · Storefront inspection

Troubleshooting an Add to cart issuejQuery-era example
  1. Isolate the app scripts.

    Inspect the storefront in DevTools. Block one app script at a time and retest Add to cart. If it works again, follow up with that app’s developer.

  2. Retest with a clean theme ZIP.

    If scripts aren’t the cause, install an unmodified copy on the same store and try the same steps.

I led theme escalations at Eight and tested fixes on a duplicate theme, giving merchants a preview they could check before publishing. I documented repeat fixes in Notion and filed GitHub issues so the team could address the underlying bugs.

Trello · Liquid · Notion · GitHub

Taking an issue to the right personHandoff paths
  1. App conflict

    Pass the reproduction to the app developer.

  2. Custom code

    Share the file differences and reproduction with the developer who made the changes.

  3. Theme bug

    Fix it on a duplicate so the merchant can preview it. Document the process in Notion and file a GitHub issue so the theme team can fix the underlying bug.

Peer QA · Code review · AI-assisted development

AI-assisted development and QAMy workflow
  1. Scope the change.

    Write a ticket with acceptance criteria so the expected behaviour is clear before development.

  2. Check the requirements.

    Use skills that reference Shopify requirements and documentation to check the relevant constraints up front.

  3. Verify the result.

    Use Claude in Chrome to check the storefront and theme editor. Hand off QA with instructions shaped by earlier human feedback.

  4. Keep what we learn.

    Record recurring issues and useful testing guidance in the knowledge base.
